## 二、根本原因

### 问题代码（v1.0）

```js
function openLink(i) {
  const l = byNo[S.sel].links[i];
  window.open(l.u, '_blank', 'noopener');   // ← 问题在这里
}
```

同样的写法还出现在另外 3 处（搜索结果、平台速查、`o` 键）。

### 为什么这行会触发确认框

`window.open(url, target, features)` 的第三个参数是 **窗口特性串**。一旦传入非空的 features，浏览器就不再把这个调用当作“打开新标签页”，而是当作**新开一个弹出窗口（popup）**来处理：

- 弹出窗口是各浏览器和内置 WebView **默认管控**的行为；
- App 内置浏览器 / 企业管控浏览器 / 部分国产浏览器在拦截弹出窗口时，弹出的正是
  **“即将访问外部链接，相关内容与服务由第三方提供。”** 这类确认框；
- 而被拦截时是否放行，往往取决于“是不是一次真实的用户点击”。

而**鼠标点击 `<a href="..." target="_blank">` 走的是完全不同的代码路径**——普通链接导航，不属于弹出窗口，因此不会被拦截。

### 这就解释了你观察到的全部现象

| 现象 | 解释 |
| --- | --- |
| “回车跳转时要手动确认” | 回车/数字键走 `window.open` → 被判定为 popup → 触发确认框 |
| “我自己使用时没有这个问题” | 发起人是用**鼠标点链接**的，走真实链接导航，不经过 popup 判定 |
| “每次重新进入网页缓存都被清理” | 这是同一个环境的另一个特征：该容器给页面的是**每次全新的、无持久化的来源（origin）**，所以存储留不下来。它是**并存症状**，不是弹框的原因——即使缓存不清，`window.open` 一样会被拦 |

## 三、修复内容

### 1. 核心修复：键盘打开网址改为激活真实 `<a>`（与鼠标点击同一条路径）

```js
let _opener = null;
function openerAnchor() {
  if (!_opener) {
    _opener = document.createElement('a');
    _opener.style.display = 'none';
    _opener.rel = 'noopener noreferrer';
    document.body.appendChild(_opener);
  }
  return _opener;
}

function openURL(u) {
  if (!u) return;
  if (S.openMode === 'same') {                 // 当前标签页：普通导航
    try { location.assign(u); } catch (e) { location.href = u; }
    return;
  }
  const a = openerAnchor();                    // 新标签页：真实链接点击
  a.href = u; a.target = '_blank'; a.click();
  toast('已在新标签页打开：' + u, u);
}
```

**全部 4 处 `window.open` 均已替换**，可执行代码中已不存在 `window.open(`。

### 2. 新增「打开方式」开关，应对仍然被拦的环境

如果目标环境对所有跨域导航都要确认，可用 `t` 键切换成**当前标签页**方式（`location.assign`，普通跳转，不经过 popup 判定）：

- 顶部按钮「打开方式：新标签页 / 当前标签页」，点击或按 `t` 切换；
- 切到“当前标签页”时按钮变琥珀色高亮，一眼可辨；
- 设置会记住（见下条）。

### 3. 新增底部提示条 + 兜底复制

每次打开网址后在底部显示一条轻提示：**已在新标签页打开：<网址> [复制链接] [×]**

- 万一仍被环境拦截，用户能立刻看到完整网址并一键复制，手动粘到浏览器即可，不必回到页面找链接；
- 6 秒后自动消失。

### 4. 状态持久化：localStorage + URL hash 双写

针对“缓存被清空”：

- 当前模块与打开方式**同时**写入 `localStorage` 和 URL 的 `#m=<模块号>&t=<方式>`；
- 每次切换模块用 `history.replaceState` 更新 hash，不污染后退历史；
- **即使存储被完全清空，只要 URL 还带着 hash，就能恢复上次的模块和打开方式**（可把带 hash 的链接加为书签）。
